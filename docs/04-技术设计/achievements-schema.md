## 1. Achievements 的产品定义

### 1.1 什么是"本周成就"？

**本周成就是周报中对用户本周学习行为的正向反馈摘要**，不是独立的成就徽章系统。

它从本周已有的统计数据中**自动提炼**出值得表扬的亮点，以简短文案 + emoji 的形式展示在周报详情页和分享长图中，目的是：

- 让用户感受到"被看见"——系统注意到了 ta 的努力
- 强化正向行为——鼓励坚持复习、提高正确率、持续录入
- 提升周报分享价值——有成就亮点的周报更值得分享

### 1.2 与"成就徽章系统"的区别

| 维度 | 本周成就（V1.0 MVP） | 成就徽章系统（V1.1） |
|------|---------------------|---------------------|
| 性质 | 周报内的动态文案片段 | 独立的持久化徽章/勋章体系 |
| 生命周期 | 仅当周有效，不累积 | 永久解锁，可收集 |
| 存储 | 无需独立表，由周报生成时实时计算 | 需要 user_achievements 表 |
| 复杂度 | 纯规则匹配，无状态 | 含解锁条件、进度追踪、动画 |
| PRD 归属 | FR-602-2 周报内容项 | §1.3 明确标注 V1.1 |

> ⚠️ **关键结论：** V1.0 的 achievements 是**周报的附属展示内容**，不是独立的激励系统。不需要新建数据库表，不需要持久化成就记录。

## 2. 数据结构建议

### 2.1 每个 Achievement 包含的字段

基于前端已有模型 `AchievementItem` 和技术设计 openapi.yaml 中的草案，确认以下结构：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `type` | string (enum) | 是 | 成就类型标识，用于客户端选择样式/图标 |
| `title` | string | 是 | 成就标题，如"连续打卡7天" |
| `description` | string | 是 | 成就描述/鼓励语，如"坚持就是胜利！" |
| `icon` | string | 是 | Emoji 图标，如 🔥🎯⭐ |

> **不含的字段：** `id`（无需持久化）、`isUnlocked`（展示的即为已达成）、`achievedAt`（隐含为本周）、`progress`（非成就系统）。保持极简。

### 2.2 JSON 示例

```json
{
  "achievements": [
    {
      "type": "STREAK_7",
      "title": "连续打卡7天",
      "description": "坚持就是胜利！",
      "icon": "🔥"
    },
    {
      "type": "MASTERED_10",
      "title": "本周消灭10道题",
      "description": "精准打击，效率惊人",
      "icon": "🎯"
    }
  ]
}
```

### 2.3 生成规则

- 成就在**周报生成时（每周日 20:00）** 由服务端根据本周数据实时计算
- 每份周报最多展示 **3 条**成就（避免信息过载）
- 按优先级排序（见下方枚举），取前 3 条命中的
- 若本周无任何成就命中，返回空数组 `[]`（周报仍正常展示其他内容）
- 成就**不存入数据库**，每次查看周报详情时实时计算（或随周报缓存）

## 3. 成就类型枚举（V1.0 MVP）

以下为 V1.0 支持的成就类型，全部可从现有数据字段直接判定：

| type | 标题模板 | 描述模板 | icon | 判定条件 | 优先级 |
|------|---------|---------|------|---------|--------|
| `STREAK_7` | 连续打卡7天 | 坚持就是胜利！ | 🔥 | streak_days >= 7 且本周每日有复习 | 1 |
| `STREAK_30` | 连续打卡30天 | 月度自律达人！ | 🔥🔥 | streak_days >= 30 | 1 |
| `MASTERED_10` | 本周消灭{n}道题 | 精准打击，效率惊人 | 🎯 | mastered_questions >= 10 | 2 |
| `MASTERED_20` | 本周消灭{n}道题 | 错题克星！ | 🎯🎯 | mastered_questions >= 20 | 2 |
| `ACCURACY_75` | 正确率突破75% | 知识掌握稳步提升 | ⭐ | review_accuracy >= 75 | 3 |
| `ACCURACY_90` | 正确率突破90% | 学霸模式开启！ | ⭐⭐ | review_accuracy >= 90 | 3 |
| `REVIEW_30` | 本周复习{n}次 | 勤奋的小蜜蜂 | 📚 | review_count >= 30 | 4 |
| `NEW_10` | 本周录入{n}道错题 | 积极归档好习惯 | 📝 | new_questions >= 10 | 5 |
| `IMPROVE` | 比上周多消灭{n}题 | 进步肉眼可见！ | 📈 | mastered > prev_week_mastered 且差值>=3 | 6 |
| `FIRST_MASTER` | 首次消灭错题 | 万事开头难！ | 🏆 | mastered_questions >= 1 且历史总消灭<=5 | 7 |

> **扩展原则：** V1.0 仅支持上述 10 种硬编码规则。新增类型需走产品评审。V1.1 成就徽章系统上线后，此列表可作为徽章解锁条件的子集复用。

## 4. 版本规划建议

### 4.1 V1.0 MVP 处理方式

| 事项 | 建议 | 理由 |
|------|------|------|
| achievements 字段 | ✅ **保留在 API 中，移除 x-deferred** | PRD FR-602-2 明确要求周报含"本周成就"；前端模型已就绪 |
| 数据结构 | 采用本文档 §2 定义的 4 字段结构 | 与前端 `AchievementItem` 对齐，最小可用 |
| 成就类型 | 实现 §3 中的 10 种规则 | 覆盖打卡/消灭/正确率/复习量/进步 5 个维度 |
| 持久化 | ❌ 不建表，实时计算 | 非独立系统，无需持久化 |
| focus_knowledge.suggestion | ✅ 一并确认：固定文案模板 | 见 §4.2 |

### 4.2 focus_knowledge.suggestion 补充定义

openapi.yaml 中 `focus_knowledge.suggestion` 同样标记了 `x-deferred`，一并确认：

- **内容：** 基于薄弱知识点生成的固定模板文案
- **模板：** `"建议重点复习「{知识点名称}」，本周有{n}道相关错题未消灭"`
- **生成规则：** 取 weak_knowledge_top[0] 的名称和未消灭数拼接
- **V1.0 不做：** AI 个性化建议（V1.1 AI 模块范畴）

### 4.3 V1.1 展望

- 独立成就徽章系统（PRD §1.3 已规划）
- 成就解锁动画 + 徽章墙页面
- 成就进度追踪（如"再消灭5题解锁'百题斩将'"）
- 宠物养成联动
- 周报成就与徽章系统打通
