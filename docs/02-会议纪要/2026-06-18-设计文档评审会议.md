## 四、用户决策项（3 项）

### 决策 1：打卡断签策略
- **选项：** A. 断签归零 + 鼓励文案 / B. 保留最长连续记录
- **决策：方案 A**
- **落地：**
  - DB 不增加 `longest_streak_days`（V1.1 再加）
  - 断签时首页展示"上次连续打卡 XX 天，重新开始吧！"

### 决策 2：打卡断签是否可补签
- **选项：** A. 不允许补签 / B. 允许每月补签 1 次
- **决策：方案 B**
- **落地：**
  - users 表新增 `makeup_sign_used_this_month BOOLEAN DEFAULT FALSE`
  - 新增 API `POST /reviews/makeup-sign`（只能补签昨天）
  - 每月 1 号 00:00 定时任务重置所有用户补签状态
  - UED 在首页打卡条断签后显示补签按钮

### 决策 3：复习中 Token 过期处理
- **选项：** A. 客户端预刷新 / B. Access Token 延长至 24h
- **决策：方案 B**
- **落地：**
  - `accessTokenTTL = 24 * time.Hour`（原 2h）
  - Refresh Token 保持 30 天不变
  - 安全评估：MVP 可接受，V1.1 评估缩短至 4h + 无感刷新
