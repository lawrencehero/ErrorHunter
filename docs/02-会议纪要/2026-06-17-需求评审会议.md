# 需求评审会议纪要

> **会议主题：** 错题猎手（ErrorHunter）V1.0 需求评审  
> **参会人员：** 产品、设计、前端、后端、AI、测试  
> **日期：** 2026-06-17  
> **记录人：** @PM

## 一、开场

**@PM（产品负责人）：** 核心就一句话——做一个帮小学生和初中生"消灭错题"的应用。核心闭环是 采集 → 归因 → 复习 → 消灭 → 学情报告，MVP 先做数学单科。

---

## 二、逐模块讨论

### 🔵 模块一：错题采集（拍照 + OCR）

**@AI工程师：** 最大技术风险是 OCR 手写识别。小学生手写字迹识别率能达到 75% 就不错了。建议：
1. MVP 阶段 OCR 只承诺**印刷体**识别（试卷、练习册），准确率可以做到 98%+
2. **手写部分**（学生的错误答案）改为手动输入或选填
3. 一定要保留**原始图片**，识别结果只是辅助

**@PM：** 同意，手写识别不承诺。原始图片必须保存。

**@后端工程师：** 图片存储建议用对象存储（OSS/S3），按用户隔离。单个用户每月可能产生 500MB+ 图片数据，MVP 阶段设存储上限吗？

**@PM：** MVP 统一 **5GB 存储空间**，后续做付费分层。

**@前端工程师：** 需求说"3步内完成录入"，但流程有7步，怎么压缩？

**@PM：** 优化为3步：
| 步骤 | 用户操作 | 系统自动完成 |
|------|---------|-------------|
| 第1步 | 拍照 | 自动裁剪 + OCR识别 + 自动识别科目 |
| 第2步 | 确认/微调题目 | 自动推荐错因 + 知识点 |
| 第3步 | 选错因标签（可跳过） | 加入复习计划 |

**@设计：** 小学生错因标签做成"快捷表情"：😵看错题了 / 🤔不会做 / ✏️算错了 / 😱粗心了

### 🔵 模块二：归因分析

**@AI工程师：** 知识点树维护问题。小学约 200+ 知识点，初中约 350+ 知识点。MVP 建议：
1. 知识点由产品 + 教研团队手动整理
2. AI 推荐先做规则匹配（关键词匹配），不做模型推理
3. 积累半年数据后再上模型

**@PM：** 同意 MVP 用规则匹配。知识点树由产品协调教研整理。

**@后端工程师：** 知识点树用树形结构存储，支持多级分类。每道错题支持多标签关联。

**@测试工程师：** 错因标签允许跳过会导致学情报告不准确。建议粗分类必填、细分类选填。

**@PM：** 改为**粗分类必填、细分类选填**。

### 🔵 模块三：科学复习

**@前端工程师：** "遮挡重做"怎么实现？在 APP 里做题需要手写板 + 公式输入，开发量巨大。

**@PM：** MVP 明确：**纸上重做 + 自评**。流程：展示题目（答案遮挡）→ 纸上重做 → 点击显示答案 → 学生自评

**@后端工程师：** 复习调度引擎需要考虑：每日新增错题数不同、复习上限、积压处理、长期未登录处理。

**@PM：** 调度策略：
| 场景 | 策略 |
|------|------|
| 每日复习上限 | 20道/天，超出部分顺延到明天 |
| 积压超过 50 道 | 触发"复习大扫除"模式，按掌握度排序 |
| 超过 7 天未登录 | 召回通知；回归后生成"回归复习包"（精选10道） |
| 考试前 3 天 | "考前冲刺"模式，按知识点组卷 |

**@设计：** 参考 Anki 的卡片翻转模式，正面题目、背面答案+解题过程，自评按钮在背面。

### 🔵 模块四：消灭错题 + 激励体系

**@测试工程师：** 消灭标准需要量化，N是多少？

**@PM：** 连续 3 次自评"做对了" → 已消灭。中间任何一次"做错" → 计数器归零。已消灭 30 天后自动复活检测。

**@前端工程师：** MVP 至少包含基础激励：消灭动画 + 连续打卡天数。开发量小但体验提升大。

**@PM：** 同意，消灭动画 + 打卡天数 提升到 MVP。

### 🔵 模块五：学情报告

**@设计：** 首页 Dashboard 展示：累计/消灭/消灭率、错因分布饼图、本周趋势折线图、薄弱知识点 TOP3。

**@后端工程师：** 统计数据每天凌晨离线计算，存汇总表。实时数据走实时查询。家长周报需要对接微信，工作量不小。

**@PM：** 家长端 MVP 不做独立端，改为 APP 内生成周报图片可分享到微信。

## 三、技术方案讨论

**@后端工程师：** MVP 阶段用单体后端 + PostgreSQL + Redis + OSS，不拆微服务。

**@AI工程师：** OCR 建议接入第三方 API（百度OCR、腾讯OCR），不自研。

**@PM：** 技术选型确认：
| 模块 | MVP 方案 |
|------|---------|
| 客户端 | Flutter 跨端（iOS + Android） |
| 后端 | Go / Java 单体服务 |
| 数据库 | PostgreSQL + Redis |
| 图片存储 | 阿里云 OSS |
| OCR | 第三方 API（百度/腾讯） |
| 推送 | 极光/个推 |

## 四、测试提问汇总

| # | 问题 | PM 决策 |
|---|------|---------|
| 1 | 一个用户最多录入多少道错题？ | 不设上限，存储上限 5GB |
| 2 | 支持多少个错题本？ | 按科目自动分本，支持自定义标签 |
| 3 | 错题删除后能恢复吗？ | 软删除，30天内可恢复 |
| 4 | 支持多设备登录吗？ | 同一账号最多3台设备 |
| 5 | 小学生注册需要家长授权吗？ | 需要，注册时勾选家长同意 |
| 6 | 离线同步冲突处理？ | 以最后修改时间为准（MVP） |
| 7 | 同一道题重复录入？ | AI 相似度检测 → V1.1 |

## 九、会议结论

1. **OCR 只承诺印刷体**，手写识别降级处理
2. **复习模式为纸上重做 + APP 自评**，不做在线答题
3. **粗分类错因必填**，细分类选填
4. **MVP 一套通用 UI**，风格偏年轻活泼
5. **Sprint 1 先出骨架版**，快速验证核心流程
6. **家长端 MVP 只做分享图片**，不做独立小程序
7. **消灭标准：连续3次完全掌握**，30天后复活检测
8. **每日复习上限 20 道**，积压 >50 道触发大扫除
9. **存储上限 5GB**，软删除保留 30 天
10. **最多 3 台设备同时登录**
